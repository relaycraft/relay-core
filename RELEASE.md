# Release Process

## Overview

```
Quality Gate  →  Performance Baseline  →  Version Bump  →  Preflight  →  Tag
(ci-check.sh)    (bench + baseline)       (commit)         (CI green)   (vX.Y.Z)
                                                                              │
                        ┌─────────────────────────────────────────────────────┘
                        ▼
              CI builds & publishes
              (GitHub Release + crates.io + npm)
```

Performance benchmarks must be run **before tagging**. Commit both
`baseline_vX.Y.Z.json` and `baseline_vX.Y.Z.md` before the version bump.

## 1. Quality Gate

Must pass before any release work begins:

```bash
./scripts/ci-check.sh    # fmt → clippy → test (all crates)
```

CI must be green on `main`.

## 2. Performance Baseline

Decide the target version `X.Y.Z`, then collect a reproducible snapshot on a
quiet machine. Use `--version` so reports are labeled correctly **before** the
Cargo.toml bump:

```bash
# Run release benchmark (5 measurement rounds, 3 warmup, 30s each)
./benchmarks/bench_minimal.sh release --version X.Y.Z --runs 5 --warmup-runs 3 --duration 30
```

**Before running:**
- Close browsers and other heavy applications
- Plug in power (laptop)
- Wait for CPU temperature to stabilise (>30s idle)

**Check the output:**
- StdDev/Mean should be < 5% for throughput and latency
- If noise is too high, wait and re-run
- Confirm markdown + JSON paths printed at the end (`release_<timestamp>.md`)

**Commit the baseline and clean up:**

```bash
# Generate versioned baseline from the latest release run
./scripts/commit-baseline.sh X.Y.Z

# Remove timestamped raw runs — only versioned baselines should accumulate
rm -f benchmarks/results/release_*.json benchmarks/results/release_*.md

git add benchmarks/results/
git commit -m "perf(bench): add release baseline for vX.Y.Z"
```

Each release keeps exactly one `baseline_vX.Y.Z.(json|md)` pair. The timestamped
`release_*` snapshots are ephemeral and should not accumulate in the repository.

## 3. mitmproxy Comparison

Run the cross-proxy comparison and commit the result alongside the baseline:

```bash
./benchmarks/compare_mitmproxy.sh --duration 30 --connections 100
cp benchmarks/results/vs_mitmproxy_*.json benchmarks/results/vs_mitmproxy_vX.Y.Z.json
```

This produces a throughput ratio and P99 latency ratio against mitmproxy. The
ratios are more stable than absolute numbers (±1% across runs) and are cited in
public-facing performance claims.

## 4. Version Bump

One commit that only changes the version string:

```bash
# Edit Cargo.toml: workspace.package.version = "X.Y.Z"
# The npm packages are auto-synced by the release workflow.
```

Commit message: `chore: bump version to X.Y.Z`

Push and wait for CI to go green before proceeding.

## 5. Preflight

```bash
./scripts/release-preflight.sh X.Y.Z
```

This verifies:
- Working tree is clean
- Cargo.toml version matches the argument
- `origin/main` CI is green (requires `gh` CLI)

## 6. Tag

Tag once and push:

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

The tag triggers three workflows:
- `release.yml` — builds binaries for 5 platforms, creates GitHub Release
- `publish.yml` — publishes Rust crates to crates.io
- `publish-npm.yml` — publishes npm packages

**If the tag workflow fails**, do NOT delete/re-tag. Fix on `main`, bump to
the next patch version, and tag that instead.

## 7. Release Notes

Release notes are auto-generated by the `release.yml` workflow from `feat`
and `fix` commit subjects since the last tag.

When `benchmarks/results/baseline_vX.Y.Z.md` exists at the tagged commit,
`release.yml` **appends that report** to the GitHub Release body automatically.
No manual copy-paste is required for the performance section.

To preview the baseline report locally:

```bash
cat benchmarks/results/baseline_vX.Y.Z.md
```

## CI Benchmarks

Two additional CI workflows monitor performance on every PR:

| Workflow | Trigger | Behaviour |
|----------|---------|-----------|
| `codspeed.yml` | push main, PR | CodSpeed micro-bench regression detection (CPU-instruction counting, ±1–3% noise). Comments on PR with per-benchmark delta. |
| `benchmark-smoke.yml` | PR, weekly | E2E throughput smoke test (alert-only, non-blocking). Uploads artifacts. |

## Commit Convention

```
<type(scope): subject>
```

| Type | Use |
|------|-----|
| `feat` | New user-facing capability |
| `fix` | Bug fix |
| `perf` | Performance improvement |
| `refactor` | Internal restructuring |
| `test` | Tests |
| `docs` | Documentation |
| `chore` | Tooling, deps, maintenance |

Subject: single intent, ≤72 chars, present tense.
