# Release Process

## Overview

```
Quality Gate     →     Version Bump     →     Preflight     →     Tag
(ci-check.sh)          (commit)               (CI green)         (vX.Y.Z)
                                                                    │
                        ┌───────────────────────────────────────────┘
                        ▼
              CI builds & publishes
              (GitHub Release + crates.io + npm)
```

Performance benchmarks must be run **before tagging** and the baseline
committed as part of the release PR.

## 1. Quality Gate

Must pass before any release work begins:

```bash
./scripts/ci-check.sh    # fmt → clippy → test (all crates)
```

CI must be green on `main`.

## 2. Performance Baseline

Collect a reproducible benchmark snapshot on a quiet machine:

```bash
# Run release benchmark (5 measurement rounds, 3 warmup, 30s each)
./benchmarks/bench_minimal.sh release --runs 5 --warmup-runs 3 --duration 30
```

**Before running:**
- Close browsers and other heavy applications
- Plug in power (laptop)
- Wait for CPU temperature to stabilise (>30s idle)

**Check the output:**
- StdDev/Mean should be < 5% for throughput and latency
- If noise is too high, wait and re-run

**Commit the baseline:**

```bash
cp benchmarks/results/release_*.json benchmarks/results/baseline_vX.Y.Z.json
git add benchmarks/results/baseline_vX.Y.Z.json
```

The `.json` and `.md` reports under `benchmarks/results/` with the `release_`
prefix are not gitignored and can be committed alongside the baseline.

## 3. Version Bump

One commit that only changes the version string:

```bash
# Edit Cargo.toml: workspace.package.version = "X.Y.Z"
# The npm packages are auto-synced by the release workflow.
```

Commit message: `chore: bump version to X.Y.Z`

Push and wait for CI to go green before proceeding.

## 4. Preflight

```bash
./scripts/release-preflight.sh X.Y.Z
```

This verifies:
- Working tree is clean
- Cargo.toml version matches the argument
- `origin/main` CI is green (requires `gh` CLI)

## 5. Tag

Tag once and push:

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

The tag triggers three workflows:
- `release.yml` — builds binaries for 5 platforms, creates GitHub Release
- `publish.yml` — publishes Rust crates to crates.io
- `publish-npm.yml` — publishes npm packages

**If the tag workflow fails**, do NOT delete/re-tag. Fix on `main`, bump to
the next patch version, and tag that instead.

## 6. Release Notes

Release notes are auto-generated by the `release.yml` workflow from `feat`
and `fix` commit subjects since the last tag.

Manually add the **performance section** to the GitHub Release body:

```markdown
## Performance (vX.Y.Z)

Environment: macOS 15.x | Apple M2 Pro (12 cores) | 32 GB RAM
Benchmark: `./benchmarks/bench_minimal.sh release --runs 5 --warmup-runs 3 --duration 30`

| Metric | Mean | StdDev | DoD |
|--------|------|--------|-----|
| Cold start | XXms | ±X | <200ms |
| Idle RSS | XXMB | ±X | <50MB |
| Throughput (S1, 1KB) | XX,XXX req/s | ±XXX | >10,000 |
| P99 Latency (S1) | X.Xms | ±X.X | <5ms |
```

Copy the values from the baseline report committed in step 2.

## CI Benchmarks

Two additional CI workflows monitor performance on every PR:

| Workflow | Trigger | Behaviour |
|----------|---------|-----------|
| `codspeed.yml` | push main, PR | CodSpeed micro-bench regression detection (CPU-instruction counting, ±1–3% noise). Comments on PR with per-benchmark delta. |
| `benchmark-smoke.yml` | PR, weekly | E2E throughput smoke test (alert-only, non-blocking). Uploads artifacts. |

## Commit Convention

```
<type(scope): subject>
```

| Type | Use |
|------|-----|
| `feat` | New user-facing capability |
| `fix` | Bug fix |
| `perf` | Performance improvement |
| `refactor` | Internal restructuring |
| `test` | Tests |
| `docs` | Documentation |
| `chore` | Tooling, deps, maintenance |

Subject: single intent, ≤72 chars, present tense.
